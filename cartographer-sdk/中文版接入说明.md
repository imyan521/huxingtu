# Cartographer Device SDK 接入说明

版本：1.0.0  
适用平台：原生 Android  
最低 Android 版本：Android 8.0（API 26）  
支持架构：仅 `arm64-v8a`

## 1. SDK 功能

SDK 负责以下工作：

- 查找并连接指定 USB 雷达；
- 请求 Android USB 使用权限；
- 使用 `230400 / 8N1` 参数管理 CH340 串口；
- 解析雷达数据；
- 采集 Android 设备的加速度计和陀螺仪数据；
- 启动、停止建图并输出实时位姿；
- 获取雷达帧、轨迹和子地图；
- 保存、加载地图及查询重定位状态；
- 根据输入图片生成户型图。

SDK 不提供界面、Activity 或 Application。接入方需要在自己的 Android App 中实现按钮、地图显示和文件管理。

## 2. 硬件要求

- Android 设备必须支持 USB Host；
- Android 设备必须有加速度计和陀螺仪；
- 当前只支持 VID/PID 为 `1A86:7523` 的 CH340 雷达；
- 雷达串口固定为 `230400` 波特率、8 数据位、1 停止位、无校验；
- Android 设备 CPU 必须支持 `arm64-v8a`。

如果雷达型号或 VID/PID 不一致，SDK 将返回 `DEVICE_NOT_FOUND`。

## 3. 将 SDK 放入项目

把 `cartographer-sdk-release.aar` 复制到客户项目的：

```text
客户项目/
└── app/
    └── libs/
        └── cartographer-sdk-release.aar
```

如果 `libs` 目录不存在，需要手动创建。

## 4. 配置 Gradle

在客户项目的 `app/build.gradle.kts` 中加入：

```kotlin
android {
    defaultConfig {
        minSdk = 26

        ndk {
            abiFilters += "arm64-v8a"
        }
    }
}

dependencies {
    implementation(files("libs/cartographer-sdk-release.aar"))
    implementation("com.github.mik3y:usb-serial-for-android:3.4.6")
    implementation("androidx.appcompat:appcompat:1.6.1")
    implementation("com.google.android.material:material:1.11.0")
    implementation("org.jetbrains.kotlin:kotlin-stdlib:1.9.22")
}
```

如果使用 Groovy `build.gradle`：

```groovy
android {
    defaultConfig {
        minSdk 26
        ndk {

        }
    }
```


SDK 的 Manifest 已声明 USB Host、加速度计、陀螺仪和高速传感器权限，正常情况下会自动合并到客户 App。

## 5. 最简单方式：启动完整功能页面

如果希望直接获得与参考 App 一致的完整功能，不需要逐个调用底层接口。客户只需在自己的按钮中启动 SDK 页面：

```kotlin
import com.cartographer.sdk.CartographerSdk

startActivity(CartographerSdk.createFullExperienceIntent(this))
```

例如：

```kotlin
class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        val button = Button(this).apply {
            text = "打开雷达建图"
            setOnClickListener {
                startActivity(CartographerSdk.createFullExperienceIntent(this@MainActivity))
            }
        }
        setContentView(button)
    }
}
```

该完整页面已经包含：

- USB 雷达连接与 IMU 采集；
- 实时雷达和地图显示；
- 开始、结束建图；
- 加载最近地图继续补采；
- 重定位判断及取消补采；
- 轨迹、子地图和机器人位姿显示；
- 地图宽度、高度和面积测量；
- 地图保存、PNG 导出和户型图生成；
- 磁力计校准、磁北对齐和对齐元数据保存；
- 户型图预览、缩放、旋转和保存。

完整页面使用 SDK 内部 Activity，不会成为客户 App 的启动页，也不会替换客户的 Application。客户仍然从自己的页面主动打开它。

## 6. 自定义界面方式：标准接入流程

调用顺序必须为：

```text
initialize
    ↓ 等待 READY
requestUsbPermission
    ↓ 用户允许
connect
    ↓ 等待 CONNECTED
startMapping
    ↓
stopMapping
    ↓ 等待 FINISHED
saveMap / 获取轨迹 / 获取子地图
    ↓
disconnect
    ↓
close
```

`initialize()` 内部存在异步初始化过程。必须收到 `MappingState.READY` 后再调用 `startMapping()`。

## 7. Kotlin 自定义界面示例

```kotlin
package customer.example

import android.os.Bundle
import android.util.Log
import androidx.appcompat.app.AppCompatActivity
import com.cartographer.sdk.*
import java.io.File

class MappingActivity : AppCompatActivity() {

    private lateinit var sdk: CartographerSdk
    private var sdkReady = false
    private var lidarConnected = false

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        sdk = CartographerSdk.initialize(
            context = applicationContext,
            config = SdkConfig(
                snapshotIntervalMs = 100L,
                imuMinimumIntervalNs = 5_000_000L
            ),
            listener = object : CartographerListener {
                override fun onUsbDeviceFound(deviceName: String) {
                    Log.i("CartographerDemo", "发现雷达：$deviceName")
                }

                override fun onUsbPermissionResult(granted: Boolean) {
                    if (granted) {
                        checkResult(sdk.connect())
                    } else {
                        Log.e("CartographerDemo", "用户拒绝了 USB 权限")
                    }
                }

                override fun onConnectionStateChanged(state: ConnectionState) {
                    lidarConnected = state == ConnectionState.CONNECTED
                    Log.i("CartographerDemo", "雷达连接状态：$state")
                }

                override fun onMappingStateChanged(state: MappingState) {
                    sdkReady = state == MappingState.READY ||
                        state == MappingState.MAPPING ||
                        state == MappingState.FINISHED
                    Log.i("CartographerDemo", "建图状态：$state")
                }

                override fun onLidarScan(scan: LidarScan) {
                    // rangesMeters 与 anglesDegrees 一一对应。
                    Log.d("CartographerDemo", "雷达点数：${scan.rangesMeters.size}")
                }

                override fun onSnapshot(snapshot: SdkSnapshot) {
                    val pose = snapshot.pose
                    if (pose != null) {
                        Log.d(
                            "CartographerDemo",
                            "x=${pose.x}, y=${pose.y}, theta=${pose.theta}"
                        )
                    }
                }

                override fun onError(code: SdkError, message: String, cause: Throwable?) {
                    Log.e("CartographerDemo", "$code: $message", cause)
                }
            }
        )
    }

    fun requestAndConnectLidar() {
        checkResult(sdk.requestUsbPermission(this))
    }

    fun startMapping() {
        if (!sdkReady) {
            Log.e("CartographerDemo", "SDK 尚未初始化完成")
            return
        }
        if (!lidarConnected) {
            Log.e("CartographerDemo", "雷达尚未连接")
            return
        }
        checkResult(sdk.startMapping())
    }

    fun stopMapping() {
        checkResult(sdk.stopMapping())
    }

    fun saveMap() {
        val output = File(filesDir, "maps/current.pbstream")
        sdk.saveMap(output) { result ->
            if (result.isSuccess) {
                Log.i("CartographerDemo", "地图已保存：${output.absolutePath}")
            } else {
                Log.e("CartographerDemo", "地图保存失败：${result.message}")
            }
        }
    }

    private fun checkResult(result: SdkResult) {
        if (!result.isSuccess) {
            Log.e("CartographerDemo", "${result.error}: ${result.message}")
        }
    }

    override fun onDestroy() {
        sdk.close()
        super.onDestroy()
    }
}
```

建议分别由按钮调用：

- “连接雷达”：`requestAndConnectLidar()`；
- “开始建图”：`startMapping()`；
- “结束建图”：`stopMapping()`；
- “保存地图”：`saveMap()`。

## 8. USB 权限与连接

请求权限：

```kotlin
val result = sdk.requestUsbPermission(this)
```

该方法必须传入当前可见的 Activity。Android 会显示 USB 授权弹窗。

收到权限成功回调后连接：

```kotlin
override fun onUsbPermissionResult(granted: Boolean) {
    if (granted) sdk.connect()
}
```

连接成功的最终依据是：

```kotlin
override fun onConnectionStateChanged(state: ConnectionState) {
    if (state == ConnectionState.CONNECTED) {
        // 可以开始建图
    }
}
```

不要在权限结果返回前直接调用 `connect()`。雷达拔出后会收到 `DEVICE_DETACHED` 错误以及断开状态。

## 9. 开始和结束建图

开始：

```kotlin
val result = sdk.startMapping()
```

必须同时满足：

- 已收到 `MappingState.READY`；
- 已收到 `ConnectionState.CONNECTED`；
- 设备具有加速度计和陀螺仪；
- 当前没有正在运行的建图任务。

结束：

```kotlin
val result = sdk.stopMapping()
```

结束过程包含最终优化。收到 `MappingState.FINISHED` 后，再保存地图或读取最终轨迹最稳妥。

## 10. 实时位姿与雷达数据

实时状态通过 `onSnapshot` 返回：

```kotlin
override fun onSnapshot(snapshot: SdkSnapshot) {
    snapshot.pose?.let { pose ->
        val xMeters = pose.x
        val yMeters = pose.y
        val headingRadians = pose.theta
    }
}
```

- `x`、`y` 单位为米；
- `theta` 单位为弧度；
- `hasPose` 表示当前是否已经得到有效位姿；
- `rangeFrames` 是已接收雷达帧数；
- `imuSamples` 是已接收 IMU 样本数；
- `insertedNodes` 是已插入轨迹节点数。

雷达帧通过 `onLidarScan` 返回：

```kotlin
override fun onLidarScan(scan: LidarScan) {
    for (index in scan.rangesMeters.indices) {
        val distanceMeters = scan.rangesMeters[index]
        val angleDegrees = scan.anglesDegrees[index]
    }
}
```

监听回调运行在主线程。不要在回调中执行大量计算或磁盘操作。

## 11. 保存和加载地图

建议保存到 App 私有目录，不需要额外存储权限：

```kotlin
val mapFile = File(filesDir, "maps/office.pbstream")
sdk.saveMap(mapFile) { result ->
    if (result.isSuccess) {
        // 保存成功
    }
}
```

加载地图前必须停止当前建图：

```kotlin
sdk.loadMap(mapFile) { result ->
    if (result.isSuccess) {
        // 地图加载成功，可开始一条新轨迹进行补采或重定位
    }
}
```

如果需要在未结束建图时保存，可传入：

```kotlin
sdk.saveMap(mapFile, includeUnfinishedSubmaps = true) { result ->
    // 处理结果
}
```

正常交付流程仍建议先 `stopMapping()`，等待 `FINISHED` 后再保存。

## 12. 获取轨迹、子地图和重定位状态

获取轨迹：

```kotlin
sdk.getTrajectory { points ->
    points.forEach { point ->
        Log.d("Trajectory", "${point.x}, ${point.y}")
    }
}
```

获取子地图纹理：

```kotlin
sdk.getSubmapTextures { textures ->
    textures.forEach { texture ->
        // pixels 为 width × height 的像素数组。
        // resolution 为地图分辨率，单位：米/像素。
    }
}
```

查询重定位状态：

```kotlin
sdk.getRelocalizationStatus { status ->
    if (status.isRelocalized) {
        Log.i("Relocalization", "重定位成功")
    }
}
```

以上接口均为异步接口，回调在主线程执行。

## 13. 生成户型图

户型图接口接收一张已经导出的地图图片，不直接接收 `.pbstream`：

```kotlin
val inputImage = File(filesDir, "floorplan/input.png")
val outputImage = File(filesDir, "floorplan/output.png")
val workDirectory = File(cacheDir, "floorplan-work")

sdk.generateFloorPlan(inputImage, outputImage, workDirectory) { result ->
    if (result.isSuccess) {
        Log.i("FloorPlan", "户型图：${outputImage.absolutePath}")
    } else {
        Log.e("FloorPlan", result.message ?: "生成失败")
    }
}
```

接入方负责把子地图渲染或拼接成输入 PNG。`workDirectory` 用于中间处理文件，建议放入 `cacheDir`。

## 14. 生命周期管理

- 一个 SDK 实例只管理一个雷达；
- 不要反复创建多个实例；
- 页面暂时切换但仍需建图时，不要在 `onPause()` 中关闭 SDK；
- 确定不再使用时调用 `close()`；
- `close()` 后该实例不可再次使用，需要重新调用 `initialize()` 创建新实例。

如果需要退到后台继续建图，客户 App 必须自己实现 Android 前台 Service。SDK 不会自动创建 Service，也不会自动申请通知权限。

## 15. 状态和错误码

连接状态：

| 状态 | 含义 |
|---|---|
| `DISCONNECTED` | 尚未连接或已经断开 |
| `CONNECTING` | 正在连接串口 |
| `CONNECTED` | 雷达连接成功 |
| `ERROR` | 串口连接或读取异常 |
| `CLOSED` | SDK 已释放 |

建图状态：

| 状态 | 含义 |
|---|---|
| `READY` | SDK 初始化完成 |
| `MAPPING` | 正在建图 |
| `FINISHED` | 建图结束且最终优化完成 |

常见错误：

| 错误码 | 原因和处理方式 |
|---|---|
| `DEVICE_NOT_FOUND` | 未找到 `1A86:7523` 雷达，检查 OTG、线缆和设备型号 |
| `PERMISSION_REQUIRED` | 尚未获得 USB 权限，先调用 `requestUsbPermission()` |
| `PERMISSION_DENIED` | 用户拒绝 USB 权限，重新插拔或再次请求 |
| `NOT_INITIALIZED` | 尚未收到 `READY` 就开始建图 |
| `SENSOR_UNAVAILABLE` | Android 设备缺少加速度计或陀螺仪 |
| `ALREADY_MAPPING` | 重复调用 `startMapping()`，或建图中尝试加载地图 |
| `NOT_MAPPING` | 没有建图任务时调用了 `stopMapping()` |
| `SERIAL_ERROR` | 串口打开、配置或读取失败，检查设备是否被其他程序占用 |
| `PROTOCOL_ERROR` | 雷达数据格式异常，检查是否使用指定雷达和协议 |
| `DEVICE_DETACHED` | 建图过程中雷达被拔出 |
| `IO_ERROR` | 地图文件不存在、目录不可写或保存加载失败 |
| `FLOOR_PLAN_FAILED` | 输入图片无效或户型图处理失败 |
| `CLOSED` | SDK 已调用 `close()`，需要重新创建实例 |

所有同步方法返回 `SdkResult`。调用方不能只调用方法而忽略结果：

```kotlin
val result = sdk.startMapping()
if (!result.isSuccess) {
    Log.e("SDK", "${result.error}: ${result.message}")
}
```

## 16. 常见问题

### 找不到雷达

确认手机或平板支持 OTG，并检查 USB 设备 VID/PID 是否确实为 `1A86:7523`。

### 出现重复 `.so` 冲突

SDK 已包含 OpenCV 和 `libc++_shared.so`。如果客户工程也包含这些库，需要统一版本，不能简单随机排除其中一份。

### x86 模拟器无法运行

SDK 仅包含 `arm64-v8a`，必须使用 ARM64 真机。普通 x86/x86_64 模拟器不能运行。

### 已连接但没有地图

检查是否依次收到 `READY`、`CONNECTED` 和 `MAPPING`，并观察 `rangeFrames`、`imuSamples` 是否持续增长。

### 户型图接口无法读取 pbstream

这是正常行为。户型图接口的输入必须是 PNG 等地图图片，不能直接传入 `.pbstream`。

## 17. 交付文件校验

客户收到 AAR 后，应核对 SHA-256：

```text
cartographer-sdk-release.aar.sha256
```

Linux/macOS：

```shell
sha256sum cartographer-sdk-release.aar
```

Windows PowerShell：

```powershell
Get-FileHash .\cartographer-sdk-release.aar -Algorithm SHA256
```

计算结果必须与随 SDK 提供的 `.sha256` 文件一致。
